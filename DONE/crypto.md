## Crypto-asset holdings (BTC, ETH, …)
(REQUIREMENTS "New Requirements — Crypto-asset holdings", added 2026-06-07. The ATO treats investment crypto as a CGT asset, so the existing parcel-level CGT machinery — parcel allocations, reduced cost base, the 12-month 50% discount, loss netting, holding-account transfers — applies unchanged; the work is letting a listing exist without an exchange. BTC/ETH are already seeded in `currencies` as DigitalToken rows (ISO 24165), refreshed by the monthly currency import. Foreign-currency cash balances are deferred — Div 775 forex gains are ordinary income, not CGT, and will be specified separately.)

## Crypto wallet-to-wallet transfer with a network fee
(REQUIREMENTS "Crypto wallet-to-wallet transfer with a network fee", added 2026-06-08. A crypto wallet-to-wallet move is already a holding-account transfer — not a CGT event. The on-chain network fee paid in the crypto is the exception: per the ATO, a holding reducing to cover a network fee is a disposal with capital-gain consequences. The fee rides on the existing transfer operation as an optional, ordinary disposal Sell — counted by the gains reports — that is created and deleted atomically with the transfer.)
- [x] Migration: `transfers.fee_sale_trade_id` (nullable FK → trades.id) links a transfer to its network-fee disposal Sell — migration `0002_transfer_network_fee.sql` (`ALTER TABLE transfers ADD COLUMN …`; no data dropped). The column is on `transfers` (not a `trades` provenance column) precisely because the fee Sell is a *real disposal* that must keep `transfer_id` NULL so the gains queries (`… AND transfer_id IS NULL`) still count it
- [x] `PUT /transfers/:id` accepts an optional fee: `fee_allocations` (source parcels/units disposed to pay the fee, same shape as the moved `allocations`), `fee_market_price` (per-unit market value, listing currency), `fee_fx_rate` (default 1). The fee units become an ordinary Sell in the source account at that market value via the shared `sell::upsert_sell_in_tx` (no provenance column → counted by every gains/performance/franking report, with the 12-month discount), linked via `transfers.fee_sale_trade_id`. Moved + fee units are validated together against each parcel's capacity (both Sells share the transfer's transaction, so the existing over-allocation check sees their sum). Fee parcels are validated to the transfer's listing; a fee without a positive `fee_market_price` → 422 (`TransferError::FeeMarketPriceMissing`). Response gains `fee_sale` (the created Sell, or null) — `entities::transfer`
- [x] Immutability + atomic delete: the fee Sell is part of the transfer group — rejected by `PUT /sells` and `DELETE /sells` (`sell::is_transfer_fee_sale` → `TransferSell`) and `PUT /trades` (`trade::db_upsert` → `TransferTrade`); `DELETE /transfers/:id` removes it (and its allocations) alongside the transfer-out Sell and transfer-in Buys, restoring the whole source parcel, ordering the deletes so neither FK (`trades.transfer_id`, `transfers.fee_sale_trade_id`) dangles mid-delete under `foreign_keys = ON`
- [x] ATO documentation: the wallet-transfer/network-fee guidance ("Crypto asset investments and tax", QC 69952; retrieved 2026-06-08) mirrored into `docs/ato/crypto-cgt.md` with the verbatim quote, indexed in `docs/ato/OVERVIEW.md`. No new worked example with figures to reproduce in `ato_examples.rs` (the guidance is a rule, not an example); the rule is locked in by the unit test below instead
- [x] Web UI: the transfer form gains an optional fee-parcel allocation editor (the shared `allocationEditor`, "Network fee (optional)") + a per-unit market-value field; the body carries `fee_allocations`/`fee_market_price` only when a fee parcel is set, and the success toast names the fee disposal Sell. `web::tests::transfers_ui_present` extended to assert `fee_allocations` + `fee_market_price` ship in the bundle
- [x] Tests (`entities::transfer::tests`): `network_fee_is_disposed_and_surfaces_in_realised_gains` (1 BTC parcel; move 0.5, fee 0.001 at A$80,000/unit → a A$80-proceeds/A$60-cost/A$20 discount-eligible gain in realised gains, the transfer-out Sell absent; `transfers.fee_sale_trade_id` set, fee Sell `transfer_id` NULL); `network_fee_requires_a_positive_market_price` (missing/zero price → 422, nothing persisted); `moved_plus_fee_cannot_exceed_the_parcel` (combined capacity); `deleting_a_feed_transfer_removes_the_fee_disposal` (fee Sell + allocations gone, parcel restored, gains cleared); `fee_disposal_sell_is_immutable_individually` (PUT/DELETE /sells, PUT /trades all rejected)
